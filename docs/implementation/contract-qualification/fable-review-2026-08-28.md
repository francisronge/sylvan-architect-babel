# Review verdict: Babel Program 1, Tasks 1–2

**Overall verdict: The audit is accurate, correctly scoped, and safe to accept after five corrections.** All seven confirmed defects verify against live source. Nothing is misclassified, the renderer stays closed, and no benchmark scope leaks in. The audit missed one material provenance asymmetry, and the fingerprint has a reproducibility hole: the capture tool and manifest are not in the commit they claim to be bound to. One caveat on method: this session blocks script execution, so I could not re-run the provider-free probes; every defect was instead verified by exact code-path tracing, and each mechanism is unambiguous in source.

## Required corrections, ordered by severity

1. **Commit the frozen-boundary artifacts.** `scripts/captureContractFingerprint.mjs` and `docs/implementation/contract-qualification/` are untracked (`git status`), yet the manifest claims it "is bound to repository commit 6865921…". Checking out that commit reproduces the hashed source but not the tool or manifest itself, and the tool (`captureContractFingerprint.mjs:127-130`) records `HEAD` without checking the tree is clean — a dirty tree would silently produce a manifest attributed to a commit it doesn't match. Today the tree is clean for every hashed path (verified: empty `git diff HEAD` over all fingerprinted directories), so the binding happens to be truthful, but only by luck. Commit all three, and add (or document) a dirty-tree guard.
2. **Amend defect 6: the Gemini route loses raw bytes entirely on nonconvergence.** When normalization throws `INCOMPLETE_GENERATION` (`GENERATION_DID_NOT_CONVERGE`, `parseNormalization.js:109-122`), the Gemini catch handles only `BAD_MODEL_RESPONSE` (`parseRoutes.js:789`) and rethrows everything else bare (`parseRoutes.js:845-847`) — no `rawOutputArtifact`, no stage/model/finishReason details. The gpt/claude path attaches `rawOutputArtifact` to every normalization failure (`parseRoutes.js:1046-1061`). So identical failures are not comparable across routes, which is stronger than the audit's "carries raw bytes and some diagnostics but not the complete generation record."
3. **Add the HTTP ingress to the fingerprint's request boundary.** Three live entry points call `parseFromBody` — `api/parse.js:102` (Vercel), `server/index.js:227` (Express), `vite.config.ts:150` (dev) — and none is hashed. I verified they don't mutate the sentence, but they are the actual transport for `/api/parse` (token gate, origin policy, 16 KB body cap, rate limits) and belong inside a "request boundary" freeze. Add them and regenerate.
4. **Extend defect 3's description of the gate's blind spots.** Beyond unbound role names and `values` literals: both gates compare **sets**, not multisets, so duplicated or dropped relations whose strings appear elsewhere pass; the structural gate is one-directional (payload ⊆ raw only, `payloadFirewall.js:167-179`), so structural deletions pass; and array-valued anchors are invisible to both sides (`extractRawStructuralAnchors` matches only string values, `payloadFirewall.js:116`; `collectPayloadStructuralAnchors` collects only `typeof child === 'string'`, `payloadFirewall.js:140`). Anchor role swaps (`probe`↔`goal`) also pass.
5. **Note the mislabeled transcriber flag.** `parseRoutes.js:481` hardcodes `payload_transcribed_by_flash_lite`, but `PAYLOAD_TRANSCRIBER_MODEL` defaults to `GEMINI_MODEL` = `gemini-3.1-pro-preview` (`routeConfig.js:120`). Provenance elsewhere records the correct model (`payloadTranscriberModel`, `parseRoutes.js:314`), so this is a misleading label, not lost data — but it's exactly the kind of provenance drift Program 1 exists to eliminate.

## Confirmed findings (all seven audit defects verify)

1. **Silent sentence rewriting** — `parseApi.js:21-28`: `` `{2,} `` deletion, `[INST]`-family strips, `^(system|user|assistant|human)\s*:` line-anchored `gim` strip, `\s+`→space collapse; the sanitized string becomes `sentence` (`parseApi.js:81`) and is what the prompt embeds. Directly contradicts `systemInstruction.js:55` ("Analyze the exact input as written"). The audit's three probe results follow deterministically from these regexes.
2. **Earlier tree replaces nonconverged final stage** — `findLatestCommittedDerivationFrame` walks backward and takes the first frame with a committed root (`derivationCompiler.js:437-448`); `normalizeParseResult` still emits all stages (`parseNormalization.js:126-140`), so the returned bundle contains a nonconverged final stage alongside an earlier-stage final tree. Contradicts `systemInstruction.js:65` ("The last derivationStage must be the converged structure").
3. **Transcriber can alter relation content** — gate keys are exactly as the audit lists (`payloadFirewall.js:1-14`); `values` literals and anchor role names fall under neither list, so `blocked`→`licensed` passes both gates. Plus the extensions in correction 4.
4. **Whitespace-word Stage Record heuristic** — `derivationCompiler.js:37-41`: ≥24 chars, ≥1 letter, ≥4 `\s+`-split words; a space-free Japanese record is one "word" and fails. The error-masking claim also verifies: invalid stages are filtered (`derivationCompiler.js:236`), then `normalizeDerivationFrames` runs **before** the recorded `validationIssues` are consulted (`parseNormalization.js:51` vs `:59`), and an unresolved `refId` throws a bare `ParseApiError` with no failure details (`derivationCompiler.js:33-35, 271-274`), yielding a generic `BAD_MODEL_RESPONSE` ruleId instead of `DERIVATION_STAGE_RECORD_SUBSTANTIVE`.
5. **Non-length stop states unclassified** — `assertGenerationComplete` returns early unless `isTruncatedGeneration` (`modelRuntime.js:341-350`), which matches only `MAX_TOKENS`/`MAX_OUTPUT_TOKENS`/`LENGTH` (`modelRuntime.js:282-289`). Anthropic `stop_reason` maps straight into `finishReason` (`modelRuntime.js:817`), so `REFUSAL` passes; OpenAI `incomplete` becomes `INCOMPLETE_<reason>` (`modelRuntime.js:738-740`), so only the max-tokens reason is caught and e.g. `INCOMPLETE_CONTENT_FILTER` passes into the JSON parser.
6. **Failed generations lose the receipt** — `generationRecord` (prompt hashes, sent scalars, runId, attempts, tokens) is attached only to success returns (`parseRoutes.js:850-856, 1064-1070`); the json-parse/normalization throw sites (`parseRoutes.js:749-762, 827-842, 992-1006, 1046-1061`) attach diagnostics but never the record. Plus correction 2's Gemini-specific worsening.
7. **Gemini timeout leaks to all hosted routes** — `routeConfig.js:211-213`: `GEMINI_ROUTE_TIMEOUT_MS > 0` applies to every non-`local` route; `GEMINI_MODEL_TIMEOUT_MS` likewise (`routeConfig.js:214-216`).

Also verified: the incumbent defaults (`routeConfig.js:25-27, 121`); local route excluded from the public validator and `ParseBundle` (`parseApi.js:14`, `types.ts:164`); the durable layer genuinely disconnected — `recordEvidence.js` demands `schemaIdentity`/`model`/`effort`/`sentConfig` fields the live schema-2 record doesn't have, and `derivationalDatabase/README.md` self-describes as persistence-free; the "evidence still missing" list is correct (greps found no tests for sanitization identity, final-stage rule, transcriber gates, non-Latin stage records, refusal stops, failure receipts, or timeout ownership — the one "refusal" hit in `relationFinalRepair.test.mjs:1708` is a renderer concept); and `fixtures/raw` holds exactly the two English examples claimed.
